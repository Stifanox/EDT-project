# D3 – Pipeline wczytywania dokumentów

**Właściciel:** O1 · **Zależności:** !D1, !D2 · **Status:** patrz [`PROGRESS.md`](../../PROGRESS.md)

## Cel
Automatyczne przygotowanie dokumentów do wyszukiwania i NER: od uploadu do zaindeksowania
we wszystkich modułach, z obsługą błędów i postępu.

## Zakres
- Masowy import (wiele plików naraz) z callbackiem postępu (`on_progress(i, n, filename)`) do paska w GUI.
- Raport z importu: dodane / duplikaty / błędy.
- Spójność: jeśli indeksowanie w którymś module rzuci wyjątek, dokument zostaje w bazie, błąd
  jest logowany i pokazywany, a reszta indekserów działa dalej.
- Start aplikacji: `rebuild_indexes()` po wczytaniu z SQLite. Przewidź, że indeksery mogą mieć
  własny cache (S4, N2), więc `rebuild` dostaje pełną listę i sam decyduje, co przeliczyć.
- Przycisk „Przebuduj indeksy” (metoda w `AppServices`).

## Pliki (własność)
- `edt/services.py` → metody `ingest_file`, `ingest_many` (nowa), `add_document`, `delete_document`, `rebuild_indexes`
  (plik wspólny, ale te metody należą do O1; nie zmieniaj fabryk innych osób)
- `edt/ingest/pipeline.py` – nowy (opcjonalnie: logika importu wydzielona z fasady)
- `tests/test_pipeline.py` – nowy

## Kontrakt / API
`AppServices.ingest_many(files: Iterable[tuple[str, bytes]], on_progress=None) -> IngestReport`
(nowa metoda, wstecznie zgodna, wpis w dzienniku). `IngestReport` jest iterowalny po `IngestResult`
i ma `added`, `duplicates`, `errors`, `warnings`, `summary()`.

## Kryteria akceptacji
- [x] `ingest_many` z callbackiem postępu i raportem (dodane / duplikaty / błędy)
- [x] Błąd w jednym indekserze nie przerywa importu ani nie psuje innych indekserów (test z „psującym się” indekserem)
- [x] Usunięcie dokumentu usuwa go z repozytorium, wszystkich indeksów i plików
- [x] Po restarcie aplikacji wyszukiwanie i encje działają bez ponownego uploadu
- [x] Logowanie (`logging`) kroków i błędów
- [x] Testy `tests/test_pipeline.py` przechodzą

## Notatki z realizacji
_2026-11-04, O1_

**Co powstało** (`edt/services.py`, metody dokumentowe O1):
- `ingest_many(files, on_progress)` → `IngestReport`. `on_progress(i, n, filename)` jest wywoływane
  po każdym pliku. Duplikaty wewnątrz jednej paczki też są wykrywane.
- `IngestResult` ma nowe pola: `warnings` (problemy niekrytyczne) i `seconds` (czas pliku), oraz
  właściwość `is_duplicate`.
- `ingest_file` **nigdy nie rzuca**: błędy parsera (także nieoczekiwane), zapisu w bazie
  i wyścig duplikatów trafiają do `error`, a problemy z oryginałem i indekserami do `warnings`.
- Odporność na indeksery: każde `add/remove/rebuild` jest osobno w `try`. Błąd jest zapisywany
  jako `IndexerFailure` w `services.failures` (ostatnie 200), a indekser trafia do
  `services.stale_indexers`. `rebuild_indexes(only_stale=False)` zwraca listę błędów
  i zdejmuje flagę z indekserów, które przebudowały się poprawnie.
- `delete_document` sprząta indeksy i oryginał zawsze (idempotentnie), nawet gdy rekordu w bazie już nie ma.
- Logowanie (`logging`, logger `edt.services`): dodanie, duplikat, błąd, awaria indeksera
  (z tracebackiem), podsumowanie importu, czas przebudowy.
- Korpus przykładowy przy starcie wczytywany przez `ingest_many`.
- `pages/1_Baza_dokumentow.py`: upload przez `ingest_many` z `st.progress` i podsumowaniem.
  Pełny widok powstanie w D4.
- `tests/test_pipeline.py`: 13 testów, m.in. `FlakyIndexer` psujący się przy add/remove/rebuild.

**Restart** (kryterium 4) jest pokryty przez `tests/test_storage.py::test_restart_keeps_documents_and_rebuilds_indexes`
i sprawdzony ręcznie: dwa procesy, ta sama baza, 12 dokumentów, wyszukiwanie i encje działają.

**Decyzje**
- `IngestReport` zamiast `list[IngestResult]`: jest iterowalny jak lista, a GUI dostaje gotowe agregaty.
- Kolejność importu: baza → oryginał → indeksery. Jeśli zapis w bazie się nie uda, nic nie jest
  indeksowane. Jeśli nie uda się indekser, dokument zostaje (źródłem prawdy jest baza), a indeks
  naprawia „Przebuduj indeksy”.
- Brak przetwarzania w tle (poza zakresem). Przy długim imporcie GUI pokazuje pasek postępu.
