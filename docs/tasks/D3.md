# D3 – Pipeline wczytywania dokumentów

**Właściciel:** O1 · **Zależności:** !D1, !D2 · **Status:** patrz [`PROGRESS.md`](../../PROGRESS.md)

## Cel
Automatyczne przygotowanie dokumentów do wyszukiwania i NER: od uploadu do zaindeksowania
we wszystkich modułach, z obsługą błędów i postępu.

## Zakres
- Masowy import (wiele plików naraz) z callbackiem postępu (`on_progress(i, n, filename)`) do paska w GUI.
- Raport z importu: dodane / duplikaty / błędy.
- Spójność: jeśli indeksowanie w którymś module rzuci wyjątek, dokument zostaje w bazie, błąd
  jest logowany i pokazywany, a reszta indekserów działa dalej.
- Start aplikacji: `rebuild_indexes()` po wczytaniu z SQLite. Przewidź, że indeksery mogą mieć
  własny cache (S4, N2), więc `rebuild` dostaje pełną listę i sam decyduje, co przeliczyć.
- Przycisk „Przebuduj indeksy” (metoda w `AppServices`).

## Pliki (własność)
- `edt/services.py` → metody `ingest_file`, `ingest_many` (nowa), `add_document`, `delete_document`, `rebuild_indexes`
  (plik wspólny, ale te metody należą do O1; nie zmieniaj fabryk innych osób)
- `edt/ingest/pipeline.py` – nowy (opcjonalnie: logika importu wydzielona z fasady)
- `tests/test_pipeline.py` – nowy

## Kontrakt / API
`AppServices.ingest_many(files: Iterable[tuple[str, bytes]], on_progress=None) -> list[IngestResult]`
(nowa metoda, wstecznie zgodna, wpis w dzienniku).

## Kryteria akceptacji
- [ ] `ingest_many` z callbackiem postępu i raportem (dodane / duplikaty / błędy)

- [ ] Usunięcie dokumentu usuwa go z repozytorium, wszystkich indeksów i plików
- [ ] Po restarcie aplikacji wyszukiwanie i encje działają bez ponownego uploadu
- [ ] Logowanie (`logging`) kroków i błędów
