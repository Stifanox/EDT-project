# D2 – Repozytorium SQLite + przechowywanie plików

**Właściciel:** O1 · **Zależności:** !P0 · **Status:** patrz [`PROGRESS.md`](../../PROGRESS.md)

## Cel
Trwałe przechowywanie dokumentów i metadanych między uruchomieniami aplikacji.

## Zakres
- `SqliteDocumentRepository` implementujący `DocumentRepository`.
- Tabela `documents` (id, name, text, source_type, language, added_at ISO, size_bytes, num_pages,
  content_hash UNIQUE, metadata JSON).
- Zapis oryginału pliku w `data/files/<id><ext>` (do pobrania w widoku dokumentu) i usuwanie go razem z dokumentem.
- Podmiana w fabryce `_make_repository()`.

## Pliki (własność)
- `edt/storage/sqlite_repo.py` – nowy
- `edt/storage/files.py` – nowy (zapis/odczyt/usuwanie oryginałów)
- `edt/services.py` → tylko `_make_repository()`
- `tests/contracts/test_repository_contract.py` → dopisanie fabryki do `REPO_FACTORIES`
- `tests/test_storage.py` – nowy

## Kontrakt / API
`DocumentRepository` z `edt/interfaces.py`. Dodatkowo (poza protokołem) np.
`original_path(doc_id) -> Path | None` dla widoku D5.

## Kryteria akceptacji
- [ ] `SqliteDocumentRepository` przechodzi `test_repository_contract.py` (także z `:memory:`)
- [ ] Dane przetrwają restart aplikacji (test: zapis → nowe połączenie → odczyt)
- [ ] `content_hash` unikalny, a duplikat nie jest dodawany drugi raz
- [ ] Oryginał pliku zapisany w `data/files/` i usuwany razem z dokumentem
- [ ] `_make_repository()` zwraca repozytorium SQLite (`config.DB_PATH`)
- [ ] Usunięcie dokumentu nie zostawia osieroconych danych w tabelach O1

- Tabelę `entities` tworzy O3 (N2). Nie dodawaj do niej kluczy obcych. O3 sam reaguje na `remove_document`.
